# OShare 原生接收展示：1.0.13

日期：2026-10-21。状态：代码接入；仅编译打包，按用户要求不运行测试、不部署手机。

## 已实现的展示路径

- 使用 OShare 自带 Seedling SDK 与已安装的 `OShareConfirm2.0.upk`，显示原生状态栏胶囊、接收进度、校验 / 保存状态及完成 / 结束动画。
- 等待接收时展示卡片并保留带 session 的确认弹窗。原生进度环可打开接收邀请；接收中进度环用于取消；保存和校验时只查看详情。
- 原生卡片显示、模板版本及实例 ID 得到创建回调确认后，自动进度弹窗收起；用户主动打开的详情不自动关闭。
- 完成后保留文件通知 / 弹窗入口，使用现有已发布 content URI。结果卡片有界显示后发送 END。
- 系统不支持、解析失败、卡片创建失败 / 超时或版本不符时，继续使用现有接收弹窗和通知。

## 原始模板与确认按钮

UPK 带厂商签名；本实现只读取原文件，不改写布局、动作或签名，不重新分发厂商模板。

基线原生接受 / 拒绝动作没有 instanceId，不能区分迟到的旧任务点击。原生卡片上的这些按钮保持隐藏，继续使用现有会话确认弹窗。当前**没有完成所有接收弹窗的全量原生替换**；接入范围是系统卡片 / 胶囊、实况进度与动画，以及已带实例标识的原生进度环操作。

这项限制与原生控制器的协议副作用分开处理：代码不会调用 ConfirmSeedlingCard 的自动 ACK、原生传输单例或全局历史打开逻辑。

## 实现组成

| 文件 | 职责 |
| --- | --- |
| `OShareSeedlingResolver.java` | 独立 APK 指纹缓存；语义定位卡片 provider、原 ROM 支持判断；完整绑定 SDK 构造器、方法、回调和生命周期 |
| `OShareSeedlingAssets.java` | 读取实际安装的原始 UPK；校验标识、版本、大小、页面数据、交互显隐及带实例的取消动作；提供原生默认数据 |
| `OShareNativeReceivePresenter.java` | 会话 / 阶段与卡片实例映射；START、单宿主数据响应、全部宿主进度更新及 END；失败回退 |
| `OShareReceiveBridge.java` | 维持原有命令、文件和弹窗；协调原生呈现、底层通知、显式详情与退回路径 |

## 生命周期与动作归属

1. Seedling 能力初始化放在后台，接收宿主先完成既有连接与广播握手。
2. 每个展示阶段使用 `opairshare-<UUID>` 实例；START 的初始数据隐藏交互，系统返回匹配 UPK 版本与实例后再更新数据。
3. 卡片的 `onUpdateData` 使用 SDK 三参数 `updateData` 响应当前宿主；协议状态变化使用带强实例匹配的 `updateAllCardData` 更新各宿主。
4. 原生进度环 `cancel + instanceId` 按创建时的阶段解释。阶段切换发送旧实例 END，并生成新实例；旧实例事件被消耗，不会转到 OShare 原生传输单例。
5. 卡片 provider 的桥接动作检查调用方身份；其他 OShare 实例直接沿用原实现。
6. 隐藏展示面不等于取消传输；按 widgetCode 跟踪各宿主，销毁一个宿主不清除其他宿主的卡片。Mosey 任务继续独立运行。显式取消仍走现有命令和 session 校验。
7. 原通知作为 SDK options 中 notificationIdList 的关联通知保留，原生显示时静默更新，交由 Seedling 协调展示。失败、结束后仍有文件入口。
8. 锁屏卡片动作只打开详情，不直接接受或取消；保留原 ROM 支持条件及状态栏锁屏策略。

## 验收边界

没有执行主机测试、Android 测试、手机安装或 UI 验证。构建成功只说明项目可编译与打包；当前手机 ROM 的能力返回、模板缓存版本、原生展示回调、通知关联和锁屏交互仍待用户自行验收。

建议安装模块后重启，再从 Apple 设备发送文件观察邀请、进度胶囊、进度环取消及完成文件入口。若未出现原生卡片，原有弹窗仍应可用；相关原因写入 LSPosed 的 `OShareAirDrop` 日志。
